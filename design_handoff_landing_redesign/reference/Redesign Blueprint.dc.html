What reads as amateurish

01 · Background stack

Four background effects, stacked

.bg-grid now reads --border-strong through --grid-opacity, so it does render on light — at rgba(0,0,0,0.15) × 0.5, roughly 7.5% black on #fafaf9. Faint, unshaped, and running edge to edge beneath a radial glow and two blurred accent orbs. Four overlapping effects, none of them directed. §01 replaces all four with one star field and a single directional glow.

Cool accent on warm ground

The light set exists now, and #6d28d9 clears contrast on #fafaf9 comfortably — so this is temperature, not ratio. Both paper grounds (#fafaf9, #f0efe8) are warm greys; the accent is a cool violet; --success adds a third hue. 01

Two-zone background system

You asked for the hero to own one background and the rest of the page another. Split the page into two named zones — hero and canvas — but derive both from the same theme rather than pinning the hero to black. The hero ground is the deep end of the ramp in dark mode and a pale blue plate in light; either way it sits one clear step off the canvas, so it still reads as its own plate while the toggle visibly reaches it. The grid goes with it: a scattered star field carries the hero instead, and it lights up under the cursor.

Why the hero follows the theme

A hero pinned to one near-black in both modes reads as a foreign object in light mode — nothing else on the page is that dark, so the plate looks pasted on rather than designed in. Deriving it from the same ramp keeps the separation you asked for (one step off the canvas, in both directions) while the accent, the dots, the card and the glow all re-tune per mode from one set of tokens. One hero design, two grounds.

The star field, precisely

Around 56 dots at 1–3px, seeded from a fixed integer so positions are stable between renders and across SSR, each twinkling on its own 3–7s cycle. A second copy of the same field sits above it in --hero-star-lit, masked to a 200px radial at the cursor — so the dots near the pointer brighten and the rest stay quiet. It replaces the grid, the radial glow and both blurred orbs; only one directional wash stays, behind the card.

02

Accent: one light blue, two values

Purple at #7C6AF7 has no darker sibling to fall back to, so it survives on dark and collapses on light. The replacement is a light blue held at two values: the bright one carries the dark hero, its lit dots and every accent on ink; the steel one carries the same accents on paper. What makes the pair work is cooling the neutrals with it — both grounds now share the accent's hue at two to four percent saturation instead of pulling warm against it, so the accent reads as part of the ground rather than a sticker on it.

03

Typographic system

The branch loads four families: Geist Sans, Geist Mono, Space Grotesk as --font-display and Dancing Script as --font-script. Four families is more than a page can carry unscoped — and one of them is currently asked for at a weight it was never loaded at. Keep all four; give each exactly one job: Geist for body and UI, Space Grotesk for display at a weight that actually exists, Dancing Script scoped strictly to the rotating word, and IBM Plex Mono for metadata in place of Geist Mono, which lacks the aperture and x-height that dense technical labels need at 12–13px. Then three rules replace the 500/600/700 ladder: weight decreases as size increases, tracking tightens in proportion to size, and all metadata moves to the mono register so it stops competing with prose.

The headline bypasses all of this

The hero sets font-display font-extrabold with an inline clamp(3.5rem, 7vw, 6rem) — it never touches the text-display token, so the ramp below cannot reach it. Space Grotesk is loaded at 500/600/700; font-extrabold asks for 800 and gets a synthesised face. Either load 800 or drop to font-semibold — and move the size onto --type-display so the token governs it.

On Dancing Script

Staying — so it has to be handled rather than merely placed. Three corrections. Its x-height sits well below Space Grotesk's, so at clamp(3rem, 6vw, 5.2rem) line two reads smaller than the lines around it: size it up to roughly 1.18× the display line and set line-height: 1 on all three so the baselines settle. Replace minWidth: 10ch — a ch unit on a calligraphic face reflows the whole headline every three seconds — with a hidden sizer holding the longest word. And drop the flanking lines to 600: a script face cannot hold its own beside a synthesised 800.

05

Hero layout

The hero is a symmetric two-column grid — lg:grid-cols-2 gap-16 — carrying a radial glow, two blurred orbs and a full-bleed grid behind a three-line headline, then a status badge, context line, bio, two CTAs and social links stacked at even intervals down the left. Nothing establishes which element is first, and the background works equally hard everywhere. The revision keeps every content type you named and changes three things: an asymmetric 7/5 split, the grid swapped for a star field that lights under the cursor, and a single directional wash behind the card in place of the centred glow and two orbs. The ground itself now comes from the theme — switch the preview below to see it. The client rail drawn here in the first pass is gone at your direction; the plate ends on the CTA row.

Projects layout

The branch moves projects to a md:grid-cols-2 grid of ProjectCards — an improvement on the single column in main, but six identical 16:9 cards in three identical rows still give the section no shape, and it forces the cover image to carry every project equally. Replace it with an indexed ledger — but not the four-column table drawn in the first pass of this document, which had problems of its own. The container below is the second pass: a lead row that carries the featured project, hanging indices in the gutter, a fixed meta rail on the right, and real link anchors instead of a 20px text target. 01 · Fixed columns on a fluid page

The first pass set 44px · 1fr · 150px · 72px with three 20px gaps — 326px of chrome committed before the content column begins. At this preview width the cover plate and the title then compete inside what is left, and the description wraps to four lines.

02 · A header row the rows cannot keep

Column labels promise a table, but rows are variable-height and the stack list wraps. Nothing after the index actually aligns, so the header adds a rule and a scan line for no gain. Meta belongs in the row, labelled by position and register rather than by a heading.

03 · Six identical rows, again

Turning six identical cards into six identical rows keeps the original problem: no project is first. One lead row fixes it without adding a second layout — the same fields, given twice the space.

04 · live · src is a 20px target

Two 12.5px mono words in a 72px column, inside a row that is itself a link. Nested anchors are invalid and the target is unreachable on touch. They become bordered chips at 32px, sitting beside the row link rather than inside it — min-height: 44px below the md breakpoint.

The role field, as decided

role: string is now required on IProject, the Mongoose model, the Zod schema and the admin form, so the meta rail prints it verbatim with no fallback. One consequence to handle at sync time: a required field means every project saved before the change fails validation on its next write, so handoff/model-changes.md ends with a one-pass updateMany backfill. Set each project's real role in the admin afterwards.

One component, two densities

<ProjectLedger density="compact" /> drops the cover plate and the description, giving the home page its three-row preview. density="full" is what you see above. The archive list becomes compact with muted foregrounds — deleting the third vocabulary.

No container chrome

The rows sit directly on the canvas between one --line-strong rule at the top and hairlines between, instead of inside a bordered card with a shadow. A card around a list of cards is two containers doing one job; the rules alone carry the ledger, and hover raises a row to --zone-surface so the lift belongs to the row rather than the wrapper.

Links in the row

You listed live and repo links as required. They belong in the row, not the detail page — but nest them as real anchors beside the row link rather than inside it, or the whole row becomes an invalid nested link.
